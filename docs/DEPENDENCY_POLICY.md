# DEPENDENCY_POLICY

작성일: 2026-04-04

## 1. 목적
의존성 추가/변경 시 재현성, 보안성, 유지보수성을 보장한다.

## 2. 기본 규칙
- 패키지 매니저는 `pnpm`만 사용
- 공통 버전은 `catalog:*` 우선 사용
- `latest` 사용 금지(예외 승인 필요)
- lockfile(`pnpm-lock.yaml`)은 의도된 변경에만 포함

## 3. 추가 기준
신규 의존성 추가 전 아래를 모두 확인한다.
- 표준 API/기존 의존성으로 해결 가능한가?
- 유지보수 상태(최근 릴리즈/이슈 대응)가 양호한가?
- 번들/런타임 비용이 합리적인가?
- 라이선스 제약이 없는가?

## 4. 변경 절차
1. 변경 이유를 PR에 명시
2. 적용 범위(앱/패키지) 최소화
3. 보안 점검(`pnpm audit` 또는 동등 절차)
4. 테스트 통과 확인
5. ADR 필요 시 `docs/DECISIONS.md` 업데이트

## 5. 버전 정책
- 프레임워크/빌드도구: minor/patch는 계획된 배치로 업데이트
- 메이저 업그레이드: 별도 브랜치 + 마이그레이션 문서
- 실험 앱(tanstack/webpack)은 예외 가능하나 PR에 명시

## 6. 금지사항
- 선언 없는 transitive dependency 직접 import
- 앱 간 임의 상대경로 참조로 dependency 우회
- 미사용 의존성 방치

## 7. 정기 점검
- 월 1회: 미사용/중복 의존성 점검
- 분기 1회: 보안/라이선스 점검
- 반기 1회: 핵심 프레임워크 버전 정렬 검토
